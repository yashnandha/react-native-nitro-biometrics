# 🤝 Collaboration Guide

Welcome to the `react-native-nitro-biometrics` collaboration guide!

Whether you are an active core maintainer, an external open-source contributor, or an organization integrating this library into production, this document outlines how we collaborate, communicate, develop, and review code together.

---

## 🎯 Our Mission & Philosophy

Our goal is to provide the **fastest, safest, and most ergonomic biometric authentication library** for the React Native ecosystem, taking full advantage of the **New Architecture** and **Nitro Modules**.

When collaborating on this project, we uphold four core values:

1. **Security First**: Biometric authentication directly gates access to sensitive user data and accounts. We treat security, memory safety, and native isolation with the highest priority.
2. **Performance Obsessed**: By using Nitro Modules, we avoid the overhead of the legacy JSON bridge. We ensure JSI calls remain instantaneous and zero-overhead.
3. **Cross-Platform Parity**: A developer using this package should enjoy identical behavior, error codes, and expectations across iOS, iPadOS, Android, and emerging platforms like visionOS.
4. **Inclusive & Constructive Collaboration**: We believe in welcoming discussions, constructive feedback, empathy, and crediting everyone who helps improve the library.

---

## 🧭 How to Collaborate

### 1. Asynchronous Discussion & RFCs (Request for Comments)
- **Small fixes & docs improvements**: Feel free to open an issue or submit a Pull Request directly.
- **New features or API changes**: Before investing time writing native code, please open an **RFC Issue** or start a discussion. Describe:
  - The problem or use case.
  - Proposed TypeScript API changes in `src/NitroBiometrics.nitro.ts`.
  - Native implementation strategy for iOS (`LocalAuthentication`) and Android (`BiometricPrompt`).
  - Edge cases (e.g. device lockout, lack of hardware, user cancellation).

### 2. Working on Existing Issues
- Browse open issues labeled `help wanted` or `good first issue`.
- Comment on an issue expressing interest in tackling it so we can avoid duplicated effort.
- Need a collaborator or pair programming partner? Tag `@yashnandha` or leave a note in the issue thread!

### 3. Co-Authoring & Pair Programming
When collaborating with others on a feature or PR, please attribute co-authors in your Git commit message:

```git
feat: add biometric crypto-object signing support

Co-authored-by: Collaborator Name <collaborator@example.com>
```
GitHub will automatically recognize both authors and show credit in the contributors graph.

## 🛠️ Local Development Setup

This repository is configured as a monorepo using **Yarn Berry (v4)** workspaces.

### Prerequisites
- **Node.js**: `>= 18.0.0` (see [`.nvmrc`](./.nvmrc))
- **Yarn**: `4.x` (managed via Yarn releases in `.yarn/releases/`)
- **macOS**: Required for iOS & visionOS native compilation
- **Xcode**: `>= 15.0` with iOS 17+ SDK
- **Android Studio**: Android SDK 34+ and NDK installed

### Initial Workspace Setup

1. **Fork and clone** the repository:
   ```sh
   git clone https://github.com/<your-username>/react-native-nitro-biometrics.git
   cd react-native-nitro-biometrics
   ```

2. **Install all dependencies**:
   ```sh
   yarn install
   ```

3. **Generate Nitro C++ Bindings (Nitrogen)**:
   ```sh
   yarn nitrogen
   ```

## ⚡ The Nitro Development Workflow

Because `react-native-nitro-biometrics` is powered by Nitro Modules, understanding the build pipeline is essential:

```
src/NitroBiometrics.nitro.ts (TypeScript Spec)
           │
           ▼ (yarn nitrogen)
nitrogen/ (Generated C++ JSI bindings, HybridObject headers & Swift/Kotlin protocols)
           │
     ┌─────┴─────────────────────────────────┐
     ▼                                       ▼
ios/NitroBiometrics.swift        android/.../NitroBiometrics.kt
(iOS Native Implementation)       (Android Native Implementation)
```

### Golden Rules for Collaborators:
1. **Never edit files in `nitrogen/` or `cpp/` directly**: These files are machine-generated by Nitrogen.
2. **Update the Spec First**: Any change to method signatures, return properties, or options must be defined in `src/NitroBiometrics.nitro.ts`.
3. **Re-run Nitrogen**: Whenever you touch `*.nitro.ts`, execute `yarn nitrogen` to update the native stubs.
4. **Implement on Both Platforms**: Always provide corresponding implementations in both `ios/NitroBiometrics.swift` and `android/src/main/java/com/margelo/nitro/nitrobiometrics/NitroBiometrics.kt`.

## 📲 Running the Example App

The `example/` app is the best way to verify your changes on actual devices and simulators.

### Start the Metro Bundler
```sh
yarn example start
```

### Run on iOS
```sh
yarn example ios
```
*To open in Xcode:*
```sh
open example/ios/NitroBiometricsExample.xcworkspace
```
Native source files can be edited in Xcode under `Pods > Development Pods > react-native-nitro-biometrics`.

### Run on Android
```sh
yarn example android
```
*To open in Android Studio:*
Open the `example/android` directory in Android Studio. Source files are located under `react-native-nitro-biometrics` in the project view.

## 🌿 Git & Branching Guidelines

Please follow standard branch naming conventions:

| Branch Prefix | Purpose | Example |
| :--- | :--- | :--- |
| `feat/` | New features or capabilities | `feat/crypto-object-support` |
| `fix/` | Bug fixes or stability improvements | `fix/android-lockout-handling` |
| `docs/` | Documentation improvements | `docs/add-expo-config-plugin` |
| `perf/` | Performance optimizations | `perf/cache-can-authenticate` |
| `refactor/` | Code refactoring without behavior change | `refactor/hook-lifecycle` |
| `test/` | Adding or improving tests | `test/mock-coverage` |

### Commit Messages (Conventional Commits)

We use [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) enforced by `commitlint` and `lefthook`:

- `feat: allow custom localization keys in options`
- `fix: prevent crash when activity is finishing on Android`
- `docs: improve troubleshooting guide for visionOS`
- `chore: bump nitro-modules dependency version`

## 🔍 Code Review & PR Checklist

Every Pull Request is thoroughly reviewed before merging. Reviewers will check against this list:

### General Checklist
- [ ] Code passes TypeScript check: `yarn typecheck`
- [ ] Linter passes with no warnings: `yarn lint`
- [ ] Unit tests pass: `yarn test`
- [ ] No extraneous files committed (`.DS_Store`, build artifacts, local configuration)

### Native & Security Checklist
- [ ] **Cross-Platform Parity**: The behavior matches between iOS and Android.
- [ ] **Main Thread Safety**: All dialogs and prompts are invoked on the UI/Main thread (`DispatchQueue.main` on iOS, `activity.runOnUiThread` on Android).
- [ ] **Error Code Alignment**: Error codes conform to the standardized error strings (e.g. `'userCanceled'`, `'notEnrolled'`, `'lockout'`, etc.).
- [ ] **Zero Data Leakage**: No biometric information or private keys are exposed or logged to console/logcat.
- [ ] **Tested on Devices / Simulators**: Verified with Face ID / Fingerprint enrolled, not enrolled, and with user cancellation.

## 🚢 Releases & Versioning

Releases follow [Semantic Versioning](https://semver.org/):
- **PATCH** (`0.1.X`): Backwards-compatible bug fixes and small improvements.
- **MINOR** (`0.X.0`): New features, new options, non-breaking improvements.
- **MAJOR** (`X.0.0`): Breaking changes to API signatures or minimum platform requirements.

Releases are published to npm using:
```sh
yarn release
```
This automatically updates the changelog via conventional commits, bumps package version, tags the Git commit, and creates a GitHub Release.
